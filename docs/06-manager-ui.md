## 已实现

- 新增 `/auto-checkin` 导航与页面，复用现有 React 组件：总开关、北京时间、每日尝试次数、重试间隔、当日补执行、逐账号参加计划、今日状态与最近 500 个账号日任务。
- 显示立即签到、批量签到与失败重试入口。生产能力保持关闭，按钮禁用；直接调用后端也会拒绝。仅当日 NetworkError/ServerError 在次数、间隔与开关条件满足时允许重试；结果未确认、Pending、已成功和限流不能重复提交。
- 暂停状态明确显示“尚未安排实际签到”，配置中的时间不冒充实际执行承诺。缺少记录不显示已签到，国际版不提供模拟活跃签到。
- 账号卡片展示当日结果和计划状态；新记录存在时不再同时显示旧布尔签到徽标。会话页增加官方版本与结构尚未验证的写入暂停提示，保留原入口。
- 原设置页改为指向新计划页。旧自动签到配置写入接口明确拒绝，不自动解释或迁移旧随机窗口设置；旧文件保留，新默认配置为关闭。
- Tauri 和 HTTP host 接入相同的 manager_scheduler 配置服务，替换原 Local/随机窗口签到循环。当前后台每 15 秒读取配置并记录进程内心跳，不加载账号、保留任务、核实状态或发送请求；没有把心跳称为签到成功。
- 配置保存使用与调度一致的跨进程文件锁，以及 SHA256 配置版本比较，旧窗口不能覆盖新设置。既有配置、任务记录必须可读取且版本兼容，否则拒绝保存并保留原文件。
- 前端轮询不覆盖未保存草稿或其原始版本；保存返回后才提示成功。HTTP 新路由校验本机 Host 和同源 Origin，拒绝站外来源与 DNS 重绑定 Host。该限制只适用于新增路由，并不代表完成了整个上游 HTTP 服务的安全审查。
