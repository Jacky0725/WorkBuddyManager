# 成长计划保存与签到记录修复

## 现象和原因

勾选每日自动出发但未选择目的地时，后端会拒绝保存；原页面目的地选择需要先在下方选择单账号并查询旅行，保存错误又在更下方显示，容易误认为按钮无响应。仅凭截图不能排除其他保存错误。另一个问题是保存 API 已成功后，页面再查询状态若失败，原逻辑会显示整体操作失败，无法区分已保存与刷新失败。

签到记录中的“失败重试”原来对所有行都渲染；成功行按钮被禁用，并不表示发生了失败或重试。核对 canRetryTask：仅允许今日可重试的网络或服务器失败且满足尝试次数、时间、账号与授权等条件；成功行不符合。

## 修改与验证

在成长计划保存按钮旁直接显示错误和成功信息；旅行自动出发未设置目的地时给出选账号、查询旅行、选目的地的操作指引，保存成功后若刷新失败明确说明设置已保存。所有账号共用所选目的地，运行时仍由后端逐账号检查官方目的地。成功或已完成签到行显示“—”，其他记录保留原重试按钮和原有禁止重复提交条件。

本轮不修改成长计划、账号开关或签到记录，不主动启用聊天和旅行出发。已运行 manager-scheduler 与 growth 相关测试，共 12 项通过；安装包构建与发布状态以后续记录为准。首次自动报名完整验收仍待自然适用样本。
