# 已知限制与阶段门禁

当前不是可发布的 WorkBuddy Manager 成品。

- 主项目已有签到和同步，但普通账号 JSON 含令牌，import_local 和 export_accounts 暴露完整 token；必须在真实接入前改造。
- 国内自动签到的第三方服务许可与授权能力复用边界未确认；真实适配器应禁用，不能发送生产请求验证猜测。
- Helper 国际仿客户端自动活跃明确排除。
- 既有签到调度按 Local 时区，不满足固定北京时间 09:15 与可关闭补执行策略。
- 会话复制备份与同步备份实现不同，活动共享 DB 的复制一致性未充分保障；正式会话写入禁用到安全门禁完善。
- 官方 WorkBuddy 版本/schema、附件引用与真实账号操作没有验收结果。
- source-map-js 1.2.1 有高危拒绝服务告警，位于 Vite→PostCSS 构建依赖链，见 dependency tree 与 audit 证据；风险触发需要处理恶意 indexed source map，不能据此声称本地数据已泄露。后续开发分支做最小补丁升级并回归。
- 素材授权、完整 Windows 分发 notice 与跨平台依赖条件仍需补全。GitHub Issue API 限流，当前 Issue 检查不完整。
- 原版桌面测试存在 Windows E0425，app 分支已最小修复并通过 34 用例；原版失败日志保留。
- 自动安装、自启动、真实桌面启动和安装/卸载未验证。不能宣称 SmartScreen 可信或已代码签名。

阶段 01 的安装器仅作本地基线留存。阶段 02 及后续开发未完成，真实账号验收需用户明确授权。
