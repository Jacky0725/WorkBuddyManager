# 阶段 04：持久每日调度核心

日期：2026-10-09。本阶段实现调度核心及隔离测试，尚未替换原 host 后台循环、接入界面或注册 Windows 自启动。

## 时间与配置

`daily_scheduler.rs` 使用可注入 Clock。业务日期和计划时间固定按北京时间 UTC+08:00 计算，不读取系统 Local 时区。配置 timezone 固定为 Asia/Shanghai；当前实现针对现代北京时间，不声称覆盖历史夏令时规则。默认每日 09:15，允许修改 HH:mm；默认总开关关闭，用户启用后默认允许当日补执行。逐账号开关与账号 enabled 同时生效，只有 workbuddy/cn 进入执行队列。

关闭补执行后，首次观察时间晚于计划分钟即记录 Missed；计划分钟内可正常执行。补执行只针对当天，不追补昨天。默认每日最多两次执行尝试、间隔五分钟；可配置一次至三次。授权失效、需要人工处理、限速和能力不支持当天停止自动执行。

## 持久幂等与恢复

配置、任务状态使用版本 1 JSON。任务键包含提供方、区域、本地账号 id 和业务日期。请求前先持久写入 Pending、开始时间和尝试计数；成功或已完成的任务当天不再执行。状态损坏、未知版本或超过 16 MiB 时停止，保留原文件。日志仅含任务身份、时间、状态及不确定标记，不存令牌或原始服务端响应。

跨实例使用数据目录内的 OS 排他文件锁，覆盖整个异步执行周期。进程退出释放锁；未完成状态留在磁盘。重启遇到 Pending 或可能已提交的任务，只查询一次状态，不再次提交；确认完成记 AlreadyCompleted，无法确认记 Unknown。查询预算独立于执行预算，因此执行次数耗尽仍能进行恢复核实。

只有明确未提交的 NetworkError/ServerError 可在间隔和每日预算内重试。结果发布失败保留请求前 Pending，下一次恢复仅核实。系统日期后退至已观察日期之前停止执行；同日时钟后退到计划前也不继续队列。执行跨零点不能把返回成功错误记为前一天成功；保留旧任务不确定状态，下一 tick 独立处理新日期。

## 验证

18 个注入时钟用例覆盖计划前/到点/之后、时间前后调整、跨零点、重启、补执行开关、账号开关、断网恢复、每日预算、提交中断、三账号不同状态、坏状态文件、取消、发布失败和排他锁。锁测试还启动一个隐藏的 Windows 子进程尝试锁定同一 fixture 文件，验证真实跨进程排他。没有注册任务计划程序。

另新增一个本地 Mock HTTP 组合用例，验证调度器经过 CheckinService 实际请求 fixture server，并在重建服务和调度器后不重复请求。Mock HTTP 共 13 个测试。

最终全工程回归：Rust 817 passed，前端 24 passed，0 failed/ignored，TypeScript/Vite 构建成功。证据见 `evidence/development-all.log`、`development-frontend-test.log`、`development-frontend-build.log` 和 `phase04-results.json`。重复的单项调度回归不累计到总数。测试 wrapper 原先将未设置的进程环境恢复为空字符串，现改为删除原先不存在的变量；五个隔离变量的恢复验证见 `phase04-wrapper-environment.json`，失败记录保留。

## 尚未接入

新核心没有常驻轮询入口、桌面配置命令或 UI。原 host 的 Local 调度尚未替换，旧生产签到入口仍被禁用。用户登录自启动、关闭及卸载清理、睡眠唤醒/未登录限制和真实 UI 验收待后续接入。当前锁测试不能替代安装后的自启动冲突验收。所有签到请求仅使用本地虚构 HTTP；真实授权和积分到账没有验证。
