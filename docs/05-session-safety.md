# 阶段 05：会话安全加固与隔离验证

日期：2026-10-09。保留主项目复制、关联、预览、增量同步和分阶段恢复算法。本阶段完成安全加固，未完成官方版本兼容性或真实会话验收。

## 生产入口与兼容性

目前没有通过本产品验证的官方客户端版本/schema 组合。`session_safety::require_verified_client` 明确拒绝生产复制、同步、关联组同步与恢复写入；不会从界面参数、环境变量或 sessions 表存在推断写入许可。接口在解析官方数据路径和登录态之前返回固定中文原因。虚构 fixture 的结构不能作为真实版本白名单。

普通账号切换在备份认证和关闭客户端之前检查 manager 操作记录。有会话写入请求、未完成操作、读取/解析失败时先拒绝并保留现场；没有待恢复操作且没有会话写入请求时，普通切换可继续。生产恢复入口此时不写会话、不清理备份。

## 写入与备份

运行中的目标档客户端会阻止所有账号的共享数据库写入，删除原先“非当前账号免关”的例外；快速检查和持锁后的检查均保留。源档只读与目标档写入仍分别处理，不据此声称运行中源档的 SQLite/正文组合已经真实验收。

目标数据库预检查解析真实路径，确认位于预期数据目录，要求既有文件且可写。READ_WRITE 连接不会新建数据库；零等待 IMMEDIATE 空事务检测其他写入者后回滚。该瞬时检查不能阻止随后启动的客户端，不等于获得所有程序之间的生命周期互斥。

最小结构检查要求 id/user_id/title/cwd/created_at/updated_at/deleted_at 列及预期类型，id 为主键；这不是完整官方 schema 白名单。动态 SQL 列名加引号转义。正文路径拒绝父目录穿越、越出 projects/data 的解析路径和最终文件符号链接。其他产品命令与路径仍需阶段 07 全面审查。

写连接启用并核实 foreign_keys，要求 synchronous 至少 FULL。写前检查全部 quick_check 结果及 foreign_key_check；复制与同步数据库更新使用 IMMEDIATE 事务，提交前再次检查。失败由事务回滚。数据库、正文和关联表整体仍沿用分阶段操作记录及恢复清单，不能声称多个文件成为一个 SQLite 原子事务。

复制与同步统一使用 SQLite Backup API，包含已提交且未 checkpoint 的 WAL 数据。源连接只读，失败时不自动用写连接恢复源库。备份完成后只将目的库转为 DELETE journal 模式，避免继承源库 WAL 模式后依赖 sidecar。复制快照持久保存并回读检查；同步恢复也复核完整性、外键和最小结构。不覆盖既有同名备份，不复制主文件/WAL/SHM 三件套来冒充一致快照。

保留已有“可靠完成后清理本次临时备份、未完成保护材料”的生命周期。长期备份、恢复页面和附件引用验证尚未交付。

## 测试证据

新增 4 个 core 用例：未 checkpoint 的 WAL 可独立快照读取且不复制 sidecar、坏外键阻止正文创建、触发器外键错误使复制事务回滚、结构变化阻止创建目标正文。更新 3 个已有用例，验证国内复制、跨档复制和同步均阻止运行中写入非当前账号。

新增 8 个 `session_safety` 集成用例：生产/关联组入口提前拒绝、普通切换预检查零创建、坏操作记录保留、结构/类型/主键变化拒绝、既有外键错误不自动修复、延迟外键错误导致完整事务回滚、缺失/只读/被占用数据库拒绝、正文路径穿越拒绝。全部使用随机临时目录和虚构账号/会话。

最终回归：723 core 单元 + 19 账号安全 + 13 Mock HTTP + 5 CLI 集成 + 18 调度 + 8 会话安全 + 34 桌面 + 9 HTTP host = 829 Rust passed；前端 24 passed，共 853，0 failed/ignored，前端构建成功。见 `phase05-workspace-test.log`、`phase05-frontend-test.log`、`phase05-frontend-build.log`、`phase05-results.json`。重复回归和阶段 00 Go 测试不累计。大 chunk 与上游 vendor 编译警告保留。

首轮 2 个失败保留在 `phase05-core-first-attempt.log`：跨档旧用例要求运行中放行，已改为新安全规则；新 WAL 用例发现快照继承 WAL 模式，已通过只转换备份库模式修复。中间通过日志也保留。
