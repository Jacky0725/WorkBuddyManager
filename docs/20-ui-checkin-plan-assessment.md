# 多账号 UI 签到任务书评估与执行门槛

日期：2026-10-12。原方案见用户提供的《WorkBuddyManager 多账号自动签到功能开发任务书》。总体方向可行，重点应先验证客户端 UI，再逐级开放单账号、串行多账号和每日自动运行，而不是一次性把全链路标为完成。

## 与当前工程的对应关系

| 原方案 | 当前事实 | 修订决定 |
| --- | --- | --- |
| 复用账号与签到能力 | Manager 当前只登记两个国内账号；`checkin_service` 已有结果、适配器和 Mock；旧 HTTP 路径仍在 `checkin.rs`，生产门禁关闭 | 复用账号索引、结果模型与隔离测试；UI 适配器单独实现，HTTP 继续关闭 |
| 官方客户端 UI 自动化 | 本机 WorkBuddy 5.8.1 的可访问性树可读；账号菜单可见“Buddy加油站”、“成长计划”和积分余额控件。“成长计划”打开 Chrome 中的“WorkBuddy - 个人中心”页面，尚未观察到具体签到按钮与成功状态 | 将客户端菜单与浏览器页面分别验证；不能预设签到动作完全发生在客户端窗口内。先做只读控件发现，不写死坐标；若无稳定入口，标记不支持 |
| 多账号自动切换 | `switch::switch_account` 会关闭、重启官方客户端并写认证文件；目前未与 UI 签到共用全局操作锁，也不能只凭进程启动确认身份 | 必须加入跨进程互斥和 UI 账号身份复核；切号失败、用户干预或身份不符时不点击签到 |
| 每日调度 | `manager_scheduler` 已支持北京时间设置与持久任务记录，但生产执行关闭；客户端界面内另可见一条声称每日 09:00 签到的自动化任务，实际执行状态未独立验证 | 先保留关闭；避免与客户端既有任务重复运行。仅在登录的可交互 Windows 会话中启用，锁屏或无窗口记为需人工处理 |
| 积分 | 官方客户端账号菜单显示积分余额；现有 HTTP 积分凭证用途未验证 | UI 读数与签到流程解耦，读取失败不影响签到；不以积分增加作为唯一成功证据 |
| 安装包 | 运行中的 `0.2.0-alpha.2` 对应旧提交，缺后续生产门禁修复 | 不覆盖旧安装；新功能及门禁经测试后使用新版本号生成独立测试候选 |

本轮第一阶段只读检查使用 Windows 可访问性接口观察官方客户端窗口。其控件树可识别客户端版本、账号菜单、“Buddy加油站”、“成长计划”和积分余额控件；调试输出过滤了可能含令牌的页面地址，未保存登录凭证。在用户同意暂停操作后，点击“成长计划”仅作导航，发现其打开 Chrome 中标题为“WorkBuddy - 个人中心”的页面。浏览器自动化工具无法可靠确认该窗口 URL，随后 Chrome 标签页连接也失败，因此按工具限制停止页面检查；没有点击签到或切换账号。目前没有获得签到按钮、AutomationId、InvokePattern 或成功状态证据。客户端任务中的“已签到”等 AI 生成文字不作为服务端或 UI 的真实签到回执。

## 必须调整的实施顺序

1. 先完成 WorkBuddy 5.8.1 单账号只读 UI 诊断：核实浏览器页面的官方来源及账号身份，再查入口、控件属性、已签到/可领取/成功提示。调试输出不保存凭证或完整用户会话；若无法可靠绑定页面，停止该路径。
2. 实现纯隔离的 UI 驱动接口与模拟控件树测试，明确 `Unknown`、`NeedsUserAction`、`Unsupported`，不把“点击完成”判为成功。
3. 加入账号切换/会话操作/UI 签到共享的跨进程互斥；人工操作冲突时停止而非抢焦点。先验证单账号，再验证 A→B→C 串行与切回。
4. 只有真实单账号 UI 验收成功，才开放人工触发；只有多账号串行和中断恢复验收成功，才开放每日计划。UI 不可交互时保持暂停。
5. 新测试安装包须包含源码修复、独立版本号、构建提交与测试证据；真实客户端验收和未完成项分别列示。

## 当前结论

方案适合作为**分阶段开发目标**，但“在官方客户端窗口内自动点击签到”的具体实现假设尚不成立：当前观察到“成长计划”跳转浏览器，实际签到位置仍未知。不能直接开启多账号无人值守签到：实际签到按钮/结果和跨账号 UI 身份尚未证实，C 尚未加入，旧候选包也不是当前源码。`docs/PROJECT_TASK_V1.md` 第 12 节已补充“仅暂停受影响高风险路径”的边界。UI 方案可以继续开发和隔离测试，但生产能力保持关闭直至对应阶段有真实证据。

开发源码已新增隔离的 `ui_checkin` 状态机：切换后必须观察目标账号身份；签到状态与身份必须来自同一次客户端观察；发现可领取状态后，在点击前与点击后再次复核身份；点击完成本身只进入验证阶段，只有随后观察到客户端“已签到”才返回成功。7 项状态机测试通过。它目前没有绑定真实 Windows 驱动、调度器或前端，不能作为可用 UI 签到功能对外开放。
